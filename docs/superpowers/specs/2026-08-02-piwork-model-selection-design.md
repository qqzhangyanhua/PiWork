# PiWork 同连接模型切换设计

## 目标

让用户在设置页中，从一个已保存连接返回的可用模型列表里选择模型。切换后的模型用于新对话和后续 Run；已经启动的 Run 继续使用启动时解析到的模型。

## 范围

- 保留现有“多连接配置”和“激活连接”能力。
- 模型切换发生在单个已保存连接内部，不创建重复连接或重复凭据。
- 凭据继续只保存在 Windows 安全存储中，前端永远不读取 API Key。
- 不改变 Work、Run 或事件持久化契约。

## 交互设计

1. 用户点击配置卡片中的“测试连接”。
2. 测试成功后，卡片显示该连接返回的模型选择框，默认选中该配置当前保存的模型；如果当前模型已不在列表中，则默认选择返回列表的第一项，但不会自动保存。
3. 用户选择不同模型后，“设为当前模型”按钮可用。
4. 保存期间禁用该卡片的测试、连接激活和模型选择操作，并显示明确的进行中状态。
5. 保存成功后，卡片标题、设置页“当前使用”摘要和应用级模型标签同步更新。若配置不是激活连接，只更新它保存的模型，仍需通过现有“使用”操作激活连接。
6. 保存失败时保留原模型和用户选择，显示本地化产品错误，不暴露底层错误文本。

## 后端设计

新增 `SelectModelForConfigurationInput { configuration_id, model_id }` 与 Tauri 命令 `select_model_for_configuration`。

`ModelService::select_model` 执行以下步骤：

1. 查找稳定 ID 对应的已保存配置。
2. 从安全存储读取该配置的 API Key。
3. 使用已保存的 provider、base URL 和凭据重新获取可用模型。
4. 拒绝空模型 ID、未知配置、缺失凭据以及供应商不再返回的模型。
5. 只更新目标配置的 `model_id` 并原子持久化，保持 `active` 标记和其他配置不变。
6. 返回不含凭据的 `ModelConfigurationSummary`。

运行引擎已经在每次 Run 启动时读取当前激活配置，因此持久化成功后，后续 Run 自动使用新模型。运行中的 Run 不会重新读取配置。

## 前端数据流

- `PiWorkClient.selectModelForConfiguration(input)` 调用新的 Tauri 命令。
- `SettingsPage` 按配置 ID 保存最近一次测试返回的模型列表和草稿选择。
- 保存成功后更新 `configurations` 中对应项；只有目标配置处于激活状态时才调用 `onModelConfigured`，从而更新 `App` 持有的当前配置以及 WorkSurface 的模型标签。
- 再次测试连接时刷新模型列表，并以已保存模型为首选草稿值。

## 可访问性与视觉

- 每个选择框使用包含配置当前模型的可访问名称，避免多卡片时标签冲突。
- 状态反馈使用 `role="status"`，失败反馈使用 `role="alert"`。
- 选择框与按钮沿用现有灰阶、边框、焦点环和窄窗口布局，不引入新的弹窗。

## 测试

- Rust：成功切换、不可用模型拒绝、未知配置拒绝、激活标记不变、运行时读取新模型。
- 前端：测试后显示模型选择器、保存命令参数、激活配置同步、非激活配置不切换应用级模型、失败保留原模型。
- 集成：类型检查、完整 Vitest、生产构建、完整 Cargo 测试和实际设置页视觉检查。
