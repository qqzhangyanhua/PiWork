PiWork 过去把普通 `agent_end`、Run 完成、Member Assignment 完成和 Lead Delivery 混为同一完成信号，使模型自述的 Artifact/Validation 字符串可以令 Work 显示 Completed；我们决定只有 `DeliveryModule` 接受并持久化的有效 Lead Work Delivery 能使 `WorkStatusProjector` 投影出 Completed，Member Assignment 只有在身份、Run 归属、schema、provenance 与 Artifact admission 均通过的 Result Envelope 存在时才能完成，Lead 普通结束转为 `delivery_required` 等待，Member 普通结束进入修复/重试，Artifact 必须是规范 Workspace 内真实存在且大小受限的文件，没有对应执行 Event 的 Validation 只能标记为 unverified；继续把 `RunCompleted` 映射到 Work、相信模型输出路径、或让 Host Tool 直接更新 `works.status` 的方案被否决，因为这些路径都会绕过聚合验收条件；其后果是完成状态可从 Delivery/Assignment/Run 的持久事实确定性重建，旧的“自然结束即完成”测试与 UI 预期必须迁移，而未来浏览器、文档和 Sandbox Adapter 只能提交可验证证据，不能自行宣布交付成功。
