# PiWork 首页修正与新版项目对话流设计

## 背景

PiWork 首页已经建立了蓝灰色画布、白色圆角卡片、五个任务起点、三块信息面板和右侧活动栏，但仍存在运行时终端闪烁、导航语义重复、品牌表达不一致、首页 Composer 错位，以及项目详情页仍沿用旧视觉体系的问题。

本设计在不破坏经典项目对话流的前提下，修正首页并新增一套与首页协调的项目对话体验。

## 目标

- 返回首页时不再弹出或闪过任何终端窗口。
- 左侧品牌使用首页 3D 蓝色 π 球体，并提供克制的循环动效。
- 首页问候语中的 `Pi` 使用品牌蓝斜体强调。
- 以“新对话”作为首页入口，删除重复的“首页”导航项。
- 让首页三块信息面板与任务卡区域等宽对齐。
- 将首页 Composer 重构为统一白色工作台。
- 保留经典项目对话流，并新增默认启用的“主页延展型”新版对话流。
- 经典版与新版共享业务数据和执行能力，不复制状态管理或后端协议。

## 非目标

- 不改变 Work、Run、消息、附件、工具事件或交付物的数据模型。
- 不新增智能体中心、知识库、联网搜索等尚未实现的业务能力。
- 不重写设置页或全部工作列表页面。
- 不删除经典项目对话流。

## 已确认交互

### 导航

- 删除侧栏“首页”按钮。
- 顶部“新对话”按钮进入首页，并创建一个新的首页草稿。
- 全局“新对话”使用默认项目。
- 删除“项目”标题行右侧的新建按钮。
- 保留每个具体项目右侧的新建按钮；点击后进入首页并预选该项目。
- `Ctrl+N` 与顶部“新对话”采用相同行为。

### 品牌与问候

- 左侧品牌图标替换为从首页 3D 视觉中提取的蓝色 π 球体。
- 动效由轻微上下浮动、小角度旋转和光晕呼吸组成，不使用高频闪烁。
- `prefers-reduced-motion: reduce` 下禁用位移和旋转。
- “你好，Pi”和“今天想让 Pi 帮你完成什么？”中的 `Pi` 为独立标记，使用品牌蓝、斜体与略高字重。

### 首页信息面板

- “最近项目”“智能体技能”“环境状态”使用三个等宽列。
- 三列整体左右边界与上方五张任务卡整体左右边界一致。
- 三列共享相同高度、间距、圆角和标题基线。

### 首页 Composer

- 使用单一白色圆角工作台，不使用贯穿整行的灰色上下文栏。
- 顶部为项目与运行环境标签。
- 中部为独立、稳定的文本输入区。
- 底部左侧为附件、智能体、知识库与联网搜索工具组。
- 底部右侧为模型选择与发送按钮。
- 工具组和提交组在同一基线上；窄屏时按明确的响应式规则换行。

## 终端闪烁根因与修正

`EnvironmentStatusPanel` 每次挂载都会调用 `getRuntimeStatus()`。Rust 的 `detect_runtime_status()` 随后依次启动 `python --version`、`node --version` 和 `git --version`。这些 Tokio 子进程在 Windows 下未设置 `CREATE_NO_WINDOW`，因此返回首页时会闪过多个控制台窗口。

修正分两层：

1. Windows 进程层：环境探测命令统一设置 `CREATE_NO_WINDOW`；非 Windows 构建保持原行为。
2. 应用会话层：运行环境状态由共享缓存持有。首页重复挂载读取缓存，不重新启动进程；显式刷新才使缓存失效。

失败仍返回“未检测到”，不得把原始进程错误暴露到产品界面。

## 项目对话体验架构

### 模式

引入全局 `DetailExperience`：

```ts
type DetailExperience = "classic" | "dashboard";
```

默认值为 `dashboard`，使用本地设备持久化。项目详情头部显示“经典版 / 新版”分段切换；修改后立即影响所有项目对话。

### 隔离策略

采用“独立外壳，共享业务组件”的结构：

- 经典版继续使用现有详情外壳和现有 CSS，不改变视觉行为。
- 新版增加 `DashboardWorkDetail` 外壳。
- 两个外壳共享 `WorkTimeline`、`WorkComposer`、`WorkInspector`、Work Store 和 Tauri client。
- 新版样式只挂在 `.workspace-main--dashboard` 作用域下，禁止使用会污染经典版的裸全局选择器。

### 新版布局

- 延续首页蓝灰色画布。
- 左侧为白色圆角主对话卡：紧凑标题栏、时间线、新版 Composer。
- 右侧为独立白色圆角检查器卡；关闭时主卡扩展占满可用宽度。
- 用户消息、助手回复、执行进度、交付物与失败状态使用同一套边框、背景、圆角和语义色令牌。
- 保留自动跟随最新输出、“有新输出”按钮、停止运行、附件预览、诊断入口和检查器拖拽能力。

## 状态流

### 新对话

`WorkSurface` 持有首页草稿上下文：预选项目与草稿修订号。全局新对话或项目内新建都会增加修订号，使首页 Composer 获得干净草稿；项目内新建同时传入对应根目录。

### 详情体验

`WorkSurface` 读取持久化的详情体验偏好，根据 `classic` 或 `dashboard` 选择外壳。切换体验不修改 Work、timeline、resources、inspector 状态或运行状态。

### 环境状态

前端面板请求共享的缓存接口。缓存首次缺失时执行探测；随后返回同一状态。刷新接口不在本次首页 UI 中暴露，只为后续环境设置页保留清晰边界。

## 可访问性

- 3D Logo 保持可访问名称 `PiWork`，纯装饰光晕对辅助技术隐藏。
- 体验切换使用带可读标签的单选或分段控件，并暴露当前值。
- 删除“首页”按钮后，“新对话”在首页状态使用 `aria-current="page"`。
- Composer 工具按钮保留完整 `aria-label`，不可用功能继续声明“即将推出”。
- 动效遵循 `prefers-reduced-motion`。

## 测试与验收

### 自动化

- Rust：环境探测在 Windows 使用无窗口进程配置；会话缓存只执行一次探测。
- React：侧栏不再显示“首页”；全局新对话进入首页；具体项目新建进入首页并预选项目；项目标题行不再有新建按钮。
- React：问候中的两个 `Pi` 都有品牌强调标记。
- React：首页三块信息面板存在并采用统一容器。
- React：详情体验默认新版、可切换经典版并持久化。
- React：两种详情外壳共享相同时间线、Composer 与检查器数据。

### 手工视觉验收

- 在 1536×1024、Windows 125% DPI 下与首页参考图复核。
- 三个信息面板等宽且与任务卡整体左右边界一致。
- Composer 不出现标签越界、占位符贴边、工具图标漂移或模型区重叠。
- 经典版截图与改造前保持一致。
- 新版详情页与首页共享背景、卡片、阴影、圆角、品牌蓝和间距节奏。
- 连续从详情页返回首页至少五次，不出现任何终端窗口。

4. 重构首页 Composer。
5. 引入详情体验偏好与经典/新版切换。
6. 实现新版详情外壳及作用域样式。
