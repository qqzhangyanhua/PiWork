PiWork 曾同时通过 `EngineSupervisor` 与 Assignment/Scheduler 管线启动和控制 Work，导致 `start`、`stop`、`interrupt` 的所有者不一致且调用方必须理解两套状态机；我们决定以 Assignment pipeline 作为唯一生产执行所有者，所有 Tauri Work/Assignment 命令只调用 `ExecutionCoordinator`，由它向 `AssignmentService` 提交输入并通过 `AssignmentSchedulerHandle` 完成停止、取消和替换，`WorkService` 只保留 Work CRUD、归档与恢复，不再持有任何执行依赖；保留两套实现、让命令自行选择路径或把控制逻辑继续放在 `WorkService` 的方案被否决，因为都会重新形成浅 module 和不可原子化的控制语义；其后果是每个用户动作只有一条可审计路径，queued/running/waiting 的 Stop 可幂等落库，但新的执行后端必须实现 Coordinator 所依赖的 Assignment/Scheduler interface，而不能绕过它直接写产品状态。
