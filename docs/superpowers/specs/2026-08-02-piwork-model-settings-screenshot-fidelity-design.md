# PiWork 模型设置页截图级还原设计

## 目标

将现有模型设置页替换为用户提供截图中的设置结构与视觉，同时保留 PiWork 已有的多连接配置、激活连接、连接测试、模型选择和本机凭据存储能力。

目标页面由现有工作区侧栏、设置页标题区、设置二级导航和模型配置主区域组成。主区域以单个连接编辑器为视觉主体，并通过顶部连接标签切换多个已保存配置。Provider、连接标签和模型选择均显示对应公司的品牌 Logo。

## 范围

### 包含

- 按参考截图重建设置页布局、层级、间距、字体、边框、圆角、状态色和响应式行为。
- 新增设置二级导航，并将“模型与本地运行”显示为当前项。
- 将多配置列表改为“连接标签 + 单连接编辑器”。
- 保留新增连接、切换连接、激活连接、测试连接、更新凭据和选择模型的现有能力。
- 为 OpenAI、Anthropic、Google Gemini、OpenRouter、DeepSeek 和自定义连接提供本地 SVG 品牌标识。
- 用可访问的自定义下拉框替代无法稳定渲染图片的原生 `select`。
- 为加载、空列表、缺失凭据、测试中、测试成功、测试失败、保存中和保存失败提供明确状态。

### 不包含

- 新增模型供应商或改变现有 Provider 枚举。
- 代理、请求超时等后端尚未支持的高级网络能力。
- 删除模型连接。
- 让非模型设置导航项获得新的设置功能；它们只作为当前截图结构中的禁用导航项呈现。
- 从安全存储向前端回传已保存的 API Key。

## 页面结构

现有 `WorkSidebar` 保持工作空间导航职责。`SettingsPage` 内部重建为以下区域：

1. 设置页标题区：显示“设置”和运行偏好说明。
2. 设置二级导航：按截图分为通用、模型与运行、数据与安全、关于四组；“模型与本地运行”是当前项。
3. 模型设置主面板：显示标题、说明、连接标签栏、连接编辑卡、连接测试卡和高级选项折叠区。
4. 连接标签栏：每个已保存连接使用 Provider Logo、Provider 名称和当前状态；末尾提供“添加连接”。
5. 单连接编辑器：编辑当前标签对应的 Provider、API Key、模型和 Base URL，并提供激活连接操作。

在宽窗口中，设置二级导航和主面板并排；在较窄窗口中，二级导航收为横向可滚动分组，编辑区域保持单列且不产生水平页面滚动。

## 组件边界

### `SettingsPage`

负责加载配置列表、选中连接、激活连接、连接测试、保存结果同步，以及页面级加载和错误状态。它继续通过 `onModelConfigured` 将激活配置同步到应用级模型标签。

### `SettingsNavigation`

负责截图中的设置二级导航结构。当前只开放“模型与本地运行”；其他项保留可访问名称并以不可用状态呈现，不制造不存在的路由或功能。

### `ConnectionTabs`

负责展示和切换已保存连接，并提供“添加连接”。切换标签只改变编辑对象，不会隐式激活连接。激活连接通过明确操作完成。

### `ModelConnectionEditor`

负责一个已保存连接或新增连接的表单状态。已保存连接初始显示掩码凭据状态；只有用户点击“重置”后才出现可编辑 API Key。表单使用配置 ID 调用现有保存接口，因此更新连接不会创建重复项。

### `BrandSelect`

一个通用、受控、可访问的自定义下拉框，用于 Provider 和模型选择。触发器与列表项显示品牌 Logo，支持方向键、Home、End、Enter、Space、Escape、点击外部关闭和关闭后的焦点返回。模型项使用所属连接的 Provider Logo。

### `ProviderLogo`

集中维护 Provider 到本地 SVG 标识的映射。组件接受 Provider、尺寸和装饰性标记。`custom` 使用通用链路图形，避免误用任何供应商品牌。

## 数据与交互流程

### 加载和切换

1. 页面调用 `listModelConfigurations`。
2. 优先选中激活配置；若无激活配置则选中第一项；列表为空时进入新增状态。
3. 切换连接标签只更新编辑对象和本地状态。
4. 非激活连接提供“设为当前”操作，调用 `activateModelConfiguration`；成功后刷新标签状态并调用 `onModelConfigured`。

### 已保存连接测试

1. 已保存且存在凭据的连接调用 `testSavedModelConfiguration`，API Key 不进入前端。
2. 成功后保存返回的可用模型列表，优先选中已保存模型；若已保存模型不在结果中，则只选择结果第一项作为草稿，不自动持久化。
3. 用户选择新模型后调用 `selectModelForConfiguration`。
4. 若该连接当前激活，保存成功后同步应用级模型标签。

### 新增或更新连接

1. 新增连接从空白表单开始；更新连接时只有用户点击“重置”才输入新 API Key。
2. Provider 或凭据改变后清空旧测试结果，要求重新测试。
3. 测试通过后显示模型选择。
4. 保存调用 `saveModelConfiguration`；更新时传入原配置 ID，新增时不传 ID。
5. 保存成功后更新标签列表和编辑器状态；新建的首个连接遵循现有后端规则自动激活。

## 凭据与安全

- 前端永远不读取已保存 API Key，只依赖 `credentialConfigured` 显示掩码状态。
- 已保存连接的测试继续由后端从 Windows 凭据管理器读取 Key。
- 更新凭据只有在用户显式进入重置状态并输入新 Key 后发生。
- Logo 全部随应用本地打包，不加载第三方 CDN 或远程图片。

## 视觉规范

- 延续应用现有 Segoe UI Variable 字体与灰阶设计令牌。
- 页面外框、设置导航和内容卡使用 1px 低对比边框；主要圆角为 8–12px。
- 主背景为温和的浅灰，卡片为白色；不使用渐变、强阴影或高饱和大面积色块。
- 蓝绿色只用于当前导航、当前连接、安全提示和可操作文本；绿色只用于连接成功状态。
- 品牌 Logo 置于 18–24px 的稳定容器中，作为识别辅助，不改变截图的克制密度。
- 连接标签在宽屏横向排列，溢出时横向滚动；窄屏不压缩 Logo 或状态文字到不可读。
- 尊重 `prefers-reduced-motion`，下拉框与折叠区只使用轻量进入/退出效果。

## 错误处理

- 配置列表加载失败：在主面板显示错误说明和重试操作。
- 凭据缺失：在连接标签和编辑器中显示缺失状态，禁用使用保存凭据的测试操作，并提供重置入口。
- 连接测试失败：保留当前表单输入，清空不可继续使用的模型结果，显示本地化错误。
- 模型保存失败：保留用户选择和已保存模型，不错误更新应用级当前模型。
- 激活失败：保持原激活状态和当前编辑标签，显示连接级错误。
- 所有进行中操作按连接隔离，并禁用会造成重复提交或竞态的相关操作。

## 可访问性

- 设置主导航、连接标签和模型表单使用明确的 landmark、标题层级和可访问名称。
- 连接标签使用单选式语义表达当前编辑对象，同时以独立状态表达是否为激活连接。
- `BrandSelect` 遵循 combobox/listbox 语义，完整支持键盘操作、活动选项和焦点管理。
- 动态成功信息使用 `role="status"`，失败信息使用 `role="alert"`。
- Logo 默认装饰性隐藏；选项的文字标签始终提供完整 Provider 或模型名称。

## 测试与验收

### 前端行为测试

- 初次加载选择激活连接，空列表进入新增状态。
- 标签切换不会隐式激活连接。
- 激活连接后列表状态和应用级模型同步。
- 已保存连接测试不要求前端 API Key，成功后显示模型列表。
- 新增和更新连接传递正确参数，更新保留原配置 ID。
- Provider 或凭据改变会使旧测试结果失效。
- Provider 和模型下拉框显示正确 Logo，并完成键盘交互与焦点返回。
- 加载、凭据缺失、连接失败、保存失败和激活失败状态均可访问。

### 回归与构建

- 运行设置页和工作区相关 Vitest。
- 运行完整 `pnpm typecheck`、`pnpm test` 和 `pnpm build`。
- 若未修改 Rust 契约，不要求新增 Rust 逻辑；仍运行受影响的模型配置测试或完整 `pnpm cargo:test` 作为回归验证。

### 视觉验收

- 在参考截图约 1.65:1 的窗口比例下，对比设置页标题、二级导航、主卡宽度、间距、边框、圆角、状态色和控件高度。
- 检查 1440×900、1280×800 和 900×640，确保无截断、重叠或不可达操作。
- 检查 OpenAI、Anthropic、Google Gemini、OpenRouter、DeepSeek 和自定义连接的 Logo 映射。
- 检查浅色与系统深色环境；浅色页面必须与目标截图一致，深色模式保持现有令牌可读性。

## 实施约束

- 优先复用现有 Tauri 模型配置接口；当前后端已支持携带配置 ID 更新，因此本设计不要求扩大后端契约。
- 不重构与设置页无关的工作区代码。
- 保留工作区中用户已有的未提交改动，提交时仅包含本功能相关文件。
