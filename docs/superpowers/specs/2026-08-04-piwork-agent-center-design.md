# PiWork 智能体中心设计

## 背景

Magic Factory 能力地图定义了 9 大能力域、96 个智能体能力单元，以及业务编排智能体、专业作业智能体和中台控制智能体三层产品结构。PiWork 当前侧栏已经保留“智能体中心”入口，但入口处于禁用状态；首页的“探索智能体”“更多技能”和能力使用按钮也仍是占位。

本次工作把能力地图完整落入 PiWork 智能体中心，并让用户能从能力详情启动一条带结构化提示的新对话。页面沿用现有主页与对话页的视觉和交互语言，不把 96 项能力包装成 96 个彼此独立的机器人。

能力数据以用户提供的 `Magic_Factory_智能体中台全量能力地图_20260804.md` 为事实来源。

## 目标

- 启用侧栏“智能体中心”入口。
- 完整展示 9 大能力域、96 项能力，以及准确的 P0/P1/P2 优先级。
- 默认用“首期推荐”降低 96 项能力带来的选择压力。
- 支持搜索、领域筛选、优先级筛选和能力详情浏览。
- 允许用户从能力详情启动新对话，并自动带入可编辑的任务草稿。
- 保持首页的冷白浅蓝仪表盘风格和对话页的专注工作区尺度。
- 为未来接入工作流、工具权限、模型路由和评测数据保留稳定的页面边界。

## 非目标

- 不实现 96 套独立智能体运行时。
- 不新增工作流编排、模型路由、权限管理、评测、成本或审计后端。
- 不宣称当前通用 PiWork 执行链路已经具备能力地图中列出的外部系统、专业工具或数据源。
- 不新增收藏、最近使用、启停、发布、灰度或市场交易能力。
- 不把能力目录数据写入 SQLite；本期数据随应用版本发布。
- 不自行翻译 96 项能力的专业正文；源内容保持中文。

## 选定方案

采用“引导式能力中心”。

首屏先解释 Magic Factory 的能力结构，突出“需求到报价”首期闭环，并展示后续建设路径和 P0 能力。用户需要完整查找时切换到“全部能力”，在那里按 9 大领域浏览和筛选 96 项能力。

未采用“目录式能力市场”，因为它会让新用户直接面对 96 项能力，缺少任务方向。未采用“业务旅程导航”，因为跨阶段能力和 AI 中台治理能力难以稳定归入单一业务阶段。

## 数据基线

### 能力域统计

| 能力域 | 数量 | P0 数量 |
| --- | ---: | ---: |
| 研创用户与创新服务 | 8 | 2 |
| 客户、线索与销售运营 | 7 | 2 |
| 需求、评估与承接决策 | 9 | 6 |
| 报价、合同、支付与财务 | 12 | 5 |
| 项目、协作与履约管理 | 10 | 1 |
| 专业工程研发 | 14 | 0 |
| 采购、试制、生产与质量 | 16 | 0 |
| 交付、售后与知识资产 | 8 | 0 |
| AI 中台运营、治理与安全 | 12 | 7 |
| **合计** | **96** | **23** |

页面和测试必须使用这里的真实统计值。早期线框中的“24 项 P0”不作为实现依据。

### 类型化数据

每项能力使用稳定 ID 和明确字段，不从 Markdown 在运行时解析：

```ts
type CapabilityPriority = "P0" | "P1" | "P2";

type AgentCapability = {
  id: number;
  name: string;
  domainId: AgentCapabilityDomainId;
  priority: CapabilityPriority;
  audiences: string[];
  coreCapability: string;
  outputs: string[];
  implementation: string;
  suggestedInputs: string[];
};
```

`name`、`audiences`、`coreCapability`、`outputs`、`implementation` 和 `priority` 忠实录入能力地图。`suggestedInputs` 是面向启动对话的简短准备提示，应依据原能力描述保守编写，不引入新的功能承诺。

领域、建设路径和能力数据放在独立数据模块中，页面组件只消费类型化数据，不内嵌 96 项长数组。

## 信息架构

### 全局入口

- `WorkspaceView` 新增 `agents`。
- 侧栏“智能体中心”由禁用按钮变为可用导航项。
- 当前视图为 `agents` 时设置 `aria-current="page"`。
- 首页、对话、全部 Work 和设置的现有状态切换逻辑保持不变。

### 页面一级结构

1. 页面工具栏：标题、说明、搜索入口。
2. 介绍区：Magic Factory 定位和 `9 大能力域 / 96 项能力 / 23 项 P0`。
3. 视图切换：“首期推荐”与“全部能力”。
4. 页面内容：推荐路径或完整能力目录。
5. 详情抽屉：在当前页面之上查看能力并启动使用。

智能体中心不复制首页右侧的“智能体活动”栏。主内容使用接近对话页的专注宽度，同时保留主页的浅蓝背景、半透明白色卡片、浅蓝描边和低对比度阴影。

## 首期推荐视图

默认进入“首期推荐”。

### 首屏介绍

- 标识：`MAGIC FACTORY · 首期推荐`。
- 主标题表达“按业务闭环组合调用专业能力”，不使用“96 个机器人”的语言。
- 三个统计卡显示 9、96、23。

### 建设路径

“需求到报价闭环”是首期高亮路径。其余三条路径作为后续方向展示：

1. 项目到样机闭环。
2. 工艺到制造闭环。
3. 平台产品化。

路径卡用于解释能力组合，不在本期创建可执行工作流。点击路径卡只更新页面内的路径说明和能力集合，不直接运行任务。

### P0 能力

首期能力区展示全部 23 项 P0 能力，可按所属领域分组或以紧凑卡片网格呈现。每张卡只展示：

- 能力名称。
- 所属领域。
- P0 标签。
- 一句核心能力摘要。

## 全部能力视图

“全部能力”包含完整的 96 项能力。

### 搜索

搜索匹配以下字段：

- 能力名称。
- 使用对象。
- 核心能力。
- 主要输出。

匹配采用不区分大小写的包含搜索。中文搜索不依赖分词服务。

### 筛选

- 能力域：全部或 9 个领域中的一个。
- 优先级：全部、P0、P1、P2。
- 搜索和两个筛选条件采用交集逻辑。
- 页面显示当前结果数量。
- 无结果时展示空态和“清除筛选”按钮。

### 能力卡片

卡片展示能力名称、领域、优先级和核心能力摘要。整张卡可用鼠标或键盘打开详情，不在列表层展示实现方式等长文本。

## 能力详情抽屉

详情从主内容右侧进入，桌面端覆盖页面的一部分，但不销毁当前搜索和筛选状态。窄窗口下抽屉变为整页覆盖层。

抽屉内容顺序：

1. 名称、领域和优先级。
2. 使用对象。
3. 核心能力。
4. 主要输出。
5. 实现方式。
6. 使用前准备。
7. “开始使用”主按钮。

抽屉支持关闭按钮、`Escape` 关闭、打开后的焦点移动和关闭后的焦点恢复。抽屉具有正确的对话框语义和可访问名称。

## 启动新对话

点击“开始使用”后：

1. 关闭详情抽屉。
2. 切换到首页的新对话视图。
3. 把结构化草稿传给现有 `NewWorkStart`。
4. 用户补充任务目标、选择项目和附件。
5. 用户主动点击发送后，才创建并启动 Work。

建议草稿格式：

```text
我想使用「{能力名称}」完成一项任务。

业务目标：

已有资料：
- {建议输入占位}

需要协助：
{核心能力}

期望输出：
- {主要输出}

补充约束或人工确认点：
```

草稿必须可编辑，不能在点击“开始使用”时自动发送。项目、附件、模型显示和创建 Work 的逻辑继续由现有 `NewWorkStart` 单一实现负责。

本期把能力落成“专业任务启动模板”。真正的工作流、知识、工具和权限配置属于后续中台能力，不在 UI 中制造已接入的假象。

## 组件边界

建议新增以下边界清晰的模块：

- `AgentCenterPage`：组合页面结构，持有视图、搜索、筛选和当前能力状态。
- `AgentCenterHero`：平台说明、真实统计和视图切换。
- `CapabilityPathCards`：建设路径与路径内能力组合说明。
- `CapabilityFilters`：搜索、领域和优先级筛选。
- `CapabilityGrid`：结果数量、卡片网格和空态。
- `CapabilityCard`：单项能力摘要和详情入口。
- `CapabilityDetailDrawer`：完整能力信息与启动操作。
- `agentCapabilities`：96 项类型化能力数据、9 个领域和路径映射。
- `capabilityPrompt`：把能力数据转换为可编辑新对话草稿的纯函数。

`WorkSurface` 负责在智能体中心和首页之间切换，并传递预填草稿。`NewWorkStart` 只增加接收初始草稿的能力，不复制或迁移现有创建 Work 逻辑。

## 状态与数据流

```mermaid
flowchart LR
    A["侧栏智能体中心"] --> B["AgentCenterPage"]
    B --> C["首期推荐"]
    B --> D["全部能力"]
    D --> E["搜索与筛选"]
    C --> F["能力卡片"]
    E --> F
    F --> G["详情抽屉"]
    G --> H["生成可编辑草稿"]
    H --> I["WorkSurface 切换首页"]
    I --> J["NewWorkStart"]
```

领域、优先级、搜索词、选中路径和当前能力都是页面局部状态。能力目录本身是只读版本数据。切换“首期推荐”和“全部能力”时保留搜索与筛选值，但推荐视图不应用这些筛选。

## 视觉设计

- 沿用 `--pw-dashboard-*` 和现有品牌色，不建立第三套全局主题。
- 页面背景延续首页冷白到浅蓝的层次。
- 卡片使用半透明白色、浅蓝描边、12–16px 圆角和低对比度阴影。
- 标题和说明保持首页的清晰层级，目录内容采用对话页的紧凑字号和信息密度。
- 品牌蓝只用于当前导航、主按钮、选中筛选和关键统计。
- P0/P1/P2 除颜色外必须始终显示文本。
- 动效只用于抽屉进入、卡片 hover 和视图内容切换，并遵守 `prefers-reduced-motion`。

## 响应式设计

- 宽桌面：3 列能力卡片，右侧详情抽屉。
- 中等宽度：2 列能力卡片，压缩横向间距。
- 窄窗口：1 列能力卡片，筛选控件换行，详情抽屉变为整页覆盖层。
- 所有尺寸下不产生横向滚动，不遮挡侧栏或主要操作。

## 国际化

- 页面导航、按钮、筛选、空态和辅助文案继续加入 `zh-CN` 与 `en` locale。
- 能力地图正文是用户提供的中文事实数据，本期在两种界面语言下均保留中文。
- 不在代码中放置未经确认的 96 项英文专业翻译。

## 空态与容错

能力数据随应用发布，不存在远程加载态。开发期和测试中若统计不满足 9 个领域、96 项能力或 23 项 P0，应直接让完整性测试失败，而不是在运行时静默隐藏问题。

运行时空态包括：

- 搜索或筛选无结果：显示当前条件说明和“清除筛选”。
- 路径映射为空：仍显示路径说明，并引导用户查看全部能力。
- 能力详情字段为空：不渲染空章节；源数据完整性测试负责阻止缺少必填字段的发布。

## 可访问性

- 侧栏导航使用 `aria-current` 表达当前页面。
- 视图切换、领域筛选和优先级筛选可以完整键盘操作。
- 能力卡片具有按钮语义和明确的可访问名称。
- 详情抽屉具有对话框语义、焦点管理和 `Escape` 行为。
- 焦点样式沿用现有 token，不能只依赖 hover。
- 优先级、筛选状态和当前视图不能只用颜色表达。

## 测试策略

### 数据完整性

- 恰好 96 项能力。
- ID 唯一并覆盖 1–96。
- 恰好 9 个领域，领域数量分别为 8、7、9、12、10、14、16、8、12。
- 恰好 23 项 P0。
- 所有必填文本、数组和领域引用有效。

### 纯逻辑

- 搜索匹配名称、使用对象、核心能力和主要输出。
- 领域、优先级和搜索采用交集逻辑。
- 能力草稿包含能力名称、核心能力、建议输入和主要输出。

### 组件与集成

- 侧栏可进入智能体中心并正确标记当前页。
- 默认显示“首期推荐”和真实统计。
- 可切换到全部能力并显示 96 项。
- 搜索、筛选、结果数量、清除筛选和空态正确。
- 能力卡片打开详情，关闭后焦点恢复。
- `Escape` 可关闭详情。
- “开始使用”进入首页并预填草稿，但不会自动发送。
- 现有首页、对话、设置和创建 Work 流程不回归。

### 完成前验证

```text
pnpm typecheck
pnpm test
pnpm build
```

## 验收标准

- 侧栏“智能体中心”可用，不再显示“即将推出”。
- 首屏准确显示 9 大能力域、96 项能力和 23 项 P0。
- 所有 96 项能力都能在“全部能力”中找到并打开详情。
- 用户可以组合搜索、领域和优先级筛选。
- 用户可以从详情启动一个带可编辑结构化草稿的新对话。
- 页面视觉上与当前主页和对话页属于同一产品，不出现独立后台模板感。
- 页面不承诺尚未接入的专业工具、外部系统或自动工作流。
- 相关测试、全量测试、类型检查和构建全部通过。
