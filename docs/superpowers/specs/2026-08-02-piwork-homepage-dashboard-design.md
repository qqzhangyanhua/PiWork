# PiWork 首页仪表盘截图级还原设计

## 目标

将 PiWork 首页替换为用户提供截图中的仪表盘布局与视觉效果，同时保留现有的项目、对话、附件、模型和执行能力。对于截图中当前产品尚未具备的能力（智能体中心、知识库、数据源、智能体活动、今日摘要、智能体技能、通知等），保留视觉结构但禁用交互，不制造尚不存在的功能承诺。

目标页面由“全局侧栏（新增顶部导航）+ 首页仪表盘主区域 + 首页专属右侧活动栏”组成。首页仪表盘取代当前默认展示的空白/最近对话列表，成为应用的默认落地页。

## 范围

### 包含

- `WorkSidebar` 新增顶部导航列表：首页 / 智能体中心 / 知识库 / 数据源 / 设置；首页设为默认视图（`App.tsx` 的 `initialView` 由 `"new"` 改为 `"home"`）。
- 保留并复用现有项目分组与对话树（`WorkSidebar` 已有能力），在“项目”分组标题旁新增一个“+”快捷入口，用于选择本地目录并新建对话。
- 首页仪表盘（`WorkHome.tsx` 重写）：
  - 顶部工具栏：身份标签（复用“本地用户”文案，非下拉交互）、“导入项目”（真实：唤起原生目录选择器并新建对话）、“探索智能体”（禁用）、通知铃铛（禁用，不显示未读红点）。
  - 问候语区块 + 简化版装饰图形。
  - 五个任务起点卡片：探索代码库 / 构建新功能 / 审查代码 / 修复问题 / 生成文档（新增真实的第 5 个起点，机制与现有 4 个一致）。
  - “最近项目”面板：真实数据，按 `rootPath` 聚合最近对话（复用 `WorkSidebar` 的聚合方式），显示相对时间、路径、“查看全部”跳转到全部对话视图。
  - “智能体技能”面板：静态占位卡片（需求分析师 / 架构设计师 / 测试工程师 / 文档助手），“使用”“更多技能”均为禁用态。
  - “环境状态”面板：真实检测本机 Python / Node.js / Git 是否可用及版本号；“配置”“查看环境详情”为禁用态。
  - 底部持续 Composer：复用现有创建/发送逻辑（项目选择、指令编辑、附件、只读模型标识、发送），新增禁用态的“智能体 / 知识库 / 联网搜索”图标与不可交互的“本地运行环境”标签。
  - 右侧“智能体活动” + “今日摘要”面板：仅首页展示，静态示例内容（含一个内联 SVG 折线图），不接入真实遥测。
- 新增 Tauri 命令，检测本机 `python` / `node` / `git` 可执行文件是否存在及版本号。
- 新增/调整中英文 i18n 文案，保持现有的键值对齐测试通过。
- 引入品牌蓝色系视觉令牌（当前导航态、主按钮、图表线条等），现有中性灰阶令牌不变。

### 不包含

- 真实的智能体中心、知识库、数据源页面与功能。
- 真实的通知系统、云账户、团队/企业版能力（沿用现有“仅此设备”表述，不采用截图中的“企业版”字样）。
- 智能体活动、今日摘要背后的真实统计/遥测采集与存储。
- Composer 内切换模型（现状仍是只读展示，`ComposerModelIndicator` 行为不变）。
- 对现有“新建对话”触发入口（侧栏“+ 新对话”、项目内“+”）已有页面流程（`NewWorkStart` 居中态）的破坏性改动；它们保持现状，仅与首页共享可复用的子组件与提交逻辑。
- 精确复刻截图中问候语旁的三维发光素材图；改用简化的 CSS/SVG 装饰图形近似呈现。

## 页面结构

```text
┌────────────────┬───────────────────────────────────────────────┬──────────────┐
│ 侧栏（全局）    │ 首页主区域                                      │ 首页右侧栏    │
│ 品牌 + 新对话   │ 顶部工具栏（身份/导入项目/探索智能体/通知）        │ 智能体活动    │
│ 首页/智能体中心/│ 问候语 + 装饰图形                                │ 今日摘要+图表 │
│ 知识库/数据源/  │ 五个任务起点卡片                                 │              │
│ 设置            │ 最近项目 | 智能体技能 | 环境状态（三栏）           │              │
│ 项目分组树      │ 底部持续 Composer                                │              │
│ 本地账户        │                                                 │              │
└────────────────┴───────────────────────────────────────────────┴──────────────┘
```

仅当 `activeView === "home"` 时渲染右侧活动栏；新建对话、对话详情、设置、全部对话视图不受影响，继续使用各自现有布局。

## 组件边界

### `WorkSidebar`（扩展）

新增“主导航”区块（首页/智能体中心/知识库/数据源/设置），渲染于品牌区与“项目”分组之间。智能体中心、知识库、数据源为禁用态导航项（保留可访问名称，不产生路由）。设置项复用既有 `onSettingsRequest`。“项目”分组标题旁新增“+”按钮，复用现有目录选择器，选择后以该目录新建对话。

### `WorkHome`（重写，容器）

负责组合首页仪表盘的所有区块，读取 `useWorkStore` 中的 works 数据用于“最近项目”，并持有仪表盘专属的本地状态（如面板展开/收起，如需要）。不直接持有创建/发送对话的表单状态，转发给复用的组合逻辑。

### `NewWorkStart`（改造为可复用）

抽出“任务起点建议行”与“持续 Composer 栏”为可被 `WorkHome` 复用的内部结构（通过 `variant` 参数与 `children` 插槽），新增第 5 个“生成文档”建议与禁用态的“智能体/知识库/联网搜索”图标、非交互式“本地运行环境”标签。创建/发送对话的提交逻辑保持单一实现，不在 `WorkHome` 中复制一份。

### `src/features/dashboard/`（新增目录）

- `DashboardHeader.tsx`：顶部工具栏（身份标签、导入项目、探索智能体、通知）。
- `RecentProjectsPanel.tsx`：真实数据的最近项目卡片列表。
- `AgentSkillsPanel.tsx`：静态占位的智能体技能卡片列表。
- `EnvironmentStatusPanel.tsx`：调用新 Tauri 命令展示 Python/Node.js/Git 检测结果。
- `AgentActivityPanel.tsx`：静态示例的智能体活动列表（首页右侧栏）。
- `DailySummaryPanel.tsx`：静态统计数字 + 一句话摘要 + 内联 SVG 折线图（首页右侧栏）。

每个面板只负责自己的展示与（如有）数据获取，通过 props 传入的回调与 `WorkHome`/`WorkSurface` 交互（如“查看全部”跳转），不直接操作全局导航状态。

### 环境检测（Rust 新增）

新增 `environment` 模块与对应 Tauri 命令（如 `get_runtime_status`），分别对 `python`/`node`/`git` 执行版本查询命令，返回是否可用及版本号字符串；查询失败按“不可用”处理，不抛出阻断性错误。命令注册进 `lib.rs` 的 `invoke_handler`，并在 `tauriClient.ts` 与 `src/test/mockTauriClient.ts` 中补充对应方法。

## 数据与交互流程

### 首页默认展示

1. 应用启动后 `initialView` 为 `"home"`。
2. `WorkHome` 从 `useWorkStore` 读取 works，按 `rootPath` 聚合出“最近项目”列表（复用 `WorkSidebar` 的聚合与排序方式），无数据时展示与现有“最近对话”一致的空态文案。
3. `EnvironmentStatusPanel` 挂载时调用新增的 `getRuntimeStatus`，展示三项检测结果；请求失败时三项均降级为“未知”而非报错阻断页面。

### 从首页发起新对话

1. 用户点击任务起点卡片、直接输入指令或使用底部 Composer。
2. 项目选择、附件、`@` 项目文件引用、发送逻辑与现有 `NewWorkStart` 完全一致（同一套提交实现）。
3. 发送成功后跳转到对话详情视图，与现有行为一致。

### 导入项目

1. 点击顶部工具栏“导入项目”调用现有的原生目录选择器。
2. 选中目录后，等价于点击侧栏项目分组的“+”：以该目录预填项目并进入新建对话视图。

### 禁用态交互

- 智能体中心 / 知识库 / 数据源 导航项、探索智能体、通知铃铛、智能体技能卡片“使用”/“更多技能”、环境状态“配置”/“查看环境详情”、Composer 中“智能体/知识库/联网搜索”图标、“本地运行环境”标签、智能体活动“全部”筛选与“查看全部活动”均渲染为 `disabled` 或非交互静态元素，保留可访问名称，不响应点击、不产生导航或提示弹层。

## 视觉规范

- 延续现有 Segoe UI Variable 字体与灰阶设计令牌（`tokens.css`）作为基础中性色。
- 新增品牌蓝色系令牌（例如 `--pw-brand-500` 等），用于：首页导航当前态背景、主要发送/操作按钮、“今日摘要”折线图。不复用现有 `--pw-accent-*`（其语义是中性灰阶，非品牌色）。
- 装饰图形使用简化的 CSS 径向渐变 + 品牌 mark（`ContinuousLoopLogo`）近似呈现问候语旁的插画，不引入外部图片资源。
- 折线图为内联 SVG，使用静态示例数据点绘制，不引入图表依赖库。
- 圆角、间距延续现有 token 序列（4/6/8px 圆角，4/8/12/16/20/24/32/40px 间距）。
- 深色模式沿用现有 dark tokens 机制，新增品牌蓝色需提供对应深色变体，保证可读性。

## 错误处理

- 环境检测失败或超时：对应项显示“未知/未检测到”，不阻断首页其余内容渲染。
- 导入项目时用户取消目录选择：无副作用，停留在首页。
- “最近项目”数据为空：展示与现有“最近对话”一致的空态文案，不展示虚假项目。
- 首页发起新对话失败：复用现有 `NewWorkStart` 的产品化错误提示逻辑，不额外引入新的错误路径。

## 可访问性

- 新增导航项、禁用态按钮均保留 `aria-label`/`aria-disabled`，明确表达“存在但当前不可用”，而非从无障碍树中彻底隐藏。
- “最近项目”“智能体技能”“智能体活动”均为列表语义，配合标题建立正确的 landmark 层级。
- 环境状态检测结果使用文本而非仅颜色表达可用/不可用。
- 折线图作为纯装饰内容，标记为 `aria-hidden`，其数据结论通过旁边的文字摘要传达。

## 测试与验收

### 前端行为测试

- 首页默认渲染顶部导航、五个任务起点（含新增“生成文档”）、三栏面板与底部 Composer。
- “最近项目”正确按 `rootPath` 聚合真实 works 数据，空数据时展示空态。
- “导入项目”调用目录选择器并在选中后进入新建对话视图，取消时无副作用。
- 禁用态导航项/按钮不触发任何回调或导航。
- `EnvironmentStatusPanel` 在成功、部分失败、全部失败三种情形下渲染正确文案。
- 首页 Composer 的创建/发送行为与 `NewWorkStart` 现有测试覆盖的场景保持一致（不因重构回归）。
- 中英文 locale 键值对齐测试（`locales.test.ts`）通过。

### 回归与构建

- 运行工作区、侧栏、首页相关 Vitest。
- 运行完整 `pnpm typecheck`、`pnpm test` 和 `pnpm build`。
- 新增 Rust 命令需运行 `pnpm cargo:test` 验证编译与既有测试不受影响。

### 视觉验收

- 对照用户提供的截图，核对侧栏结构、首页三栏面板、底部 Composer 与右侧活动栏的间距、圆角、层级和品牌蓝色使用位置。
- 检查窗口默认尺寸 1232×800 与最小尺寸 900×640 下的布局，确认无遮挡、重叠或横向滚动。
- 检查浅色与系统深色环境下新增蓝色令牌的可读性。

## 实施约束

- 不改动现有“新建对话”“对话详情”“设置”“全部对话”视图已验证的交互逻辑，只抽取可复用子结构。
- 优先复用现有数据模型（`WorkSummary`/`rootPath` 聚合方式），不为“最近项目”引入新的后端契约。
- 新增 Rust 命令保持最小化（仅只读版本检测），不引入新的持久化状态。
- 提交时仅包含本功能相关文件，保留工作区中用户已有的未提交改动。
